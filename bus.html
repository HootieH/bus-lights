🚌 Cabin Bus — System Findings & Control Notes

Reverse-engineered from the Raspberry Pi filesystem dump · single-file reference · everything you need to turn the lights on (and more) without the original hub.

TL;DR
  • This was a Cabin luxury overnight sleeper bus. Each sleeping berth ("cabin") has its own Raspberry Pi controlling its lights.
  • A central HubPi coordinated them over the bus network; this dump is from that HubPi.
  • You don't need the hub. The control script talks straight to each cabin Pi's light pins over SSH and replaces the hub entirely.
  • Way in: a recovered SSH key (now at ~/.ssh/cabin_key) + the bus's wired Ethernet. No Wi-Fi password required.
  • Tooling delivered: ~/Desktop/bus-lights.command (offline control) & this page.

1 · What the system is

The shared code library is literally named cabin-javascript-library; the Pis are named CabinPi-<serial>; berths are numbered like a coach (1A–6D, driver/passenger sides); and the software talks about vehicle scenes, guest scenes, and an emergency state. This is the Cabin overnight bus (the SF↔LA "moving hotel," ~2017–2019).

The lighting was one feature of a whole-vehicle system. The hub also did fleet telemetry: an IMU / accelerometer for ride-quality & bump logging (bumpLogging/, YostDataParser), and CradlePoint cellular-router status (onboard Wi-Fi + LTE). So the Pi network delivered guest lighting, crew control, emergency lighting, onboard internet, and remote management — which is why it isn't "just a light switch."

3 · How a light turns on

Original path (hub-driven)

  1. Crew/UI picks a scene on the hub
  2. Hub socket.io pushes event → cabin lightd
  3. hub.js dispatches into a Redux store
  4. store → computed per-light brightness
  5. LightChannel → pigpio PWM on GPIO
  6. LED driver channels → fixtures (smooth fade)

Your path (script, no hub)

  1. bus-lights.command on your Mac
  2. SSH to a cabin Pi with cabin_key
  3. stop lightd · start pigpiod
  4. pigs w/p <pin> … sets the channel
  5. LED driver channels → fixtures

Same final two steps — we just skip the hub, sockets, and Redux.

Lights can also be toggled locally at the berth: a nightstand button panel (Dallas DS2408 1-Wire chip) plus a redundant button feed the same store; the daemon reports the guest's choice back to the hub.

9 · The control script — ~/Desktop/bus-lights.command

It replaces the hub. The hub does not need to be running. The script SSHes to each cabin Pi, momentarily stops that cabin's lightd so it can take the GPIO, and drives the pins directly. Use restore to hand control back to the daemon later.

Double-click in Finder for a menu, or run from Terminal:

./bus-lights.command                 # interactive menu
./bus-lights.command discover        # which cabins are reachable
./bus-lights.command on all          # every cabin, all white lights full
./bus-lights.command off 2B          # one cabin off
./bus-lights.command dim all 25      # 25% everywhere
./bus-lights.command scene all departure
./bus-lights.command light 1A backpack 100   # just the reading light
./bus-lights.command rgb all 255 0 0         # red sign everywhere
./bus-lights.command emergency all   # all full + red
./bus-lights.command reboot 4C
./bus-lights.command restore all     # give GPIO back to the hub/daemon
./bus-lights.command run all 'uptime'        # arbitrary command on every cabin
Targetsall (default) · a cabin label (3D) · a hostname · an IP

10 · Caveats & unknowns

  • Side-of-bus mirroring. LightMap.js swaps the four valence channels based on isLeftSide. The dumped copy has isLeftSide=false; the actual per-cabin value may differ, so "top/bottom/distal/proximal" labels could mirror on some berths. The set of pins is correct regardless; only the human labels may flip.
  • Scene brightness is approximate. The exact factory levels live compiled inside cabin-javascript-library (abstract LightLevel constants) and weren't byte-for-byte extractable. Presets reproduce intent; tune numbers at the top of scene_cmds().
  • Nightstand "cloud" light + scene indicator LEDs are on the 1-Wire DS2408, not PWM GPIO — the script drives the main fixtures, not those indicator LEDs.
  • cabinsecurity-midnight password is not recoverable from this dump (it's in the CradlePoint). Use Ethernet, or reset the router.
  • Guest Wi-Fi (ridecabin) may be firewalled off the Pi management LAN. Wired Ethernet is the reliable path.
  • mDNS reachability assumes Avahi is running on the cabin Pis (it is by default on this image). If a name won't resolve, scan the subnet (nmap -p22 --open 10.101.1.0/24, or arp -a + the MACs above) and SSH to the IP.
